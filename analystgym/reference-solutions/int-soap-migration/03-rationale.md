# Перевод интеграции с SOAP на REST без остановки потока

Задача: `int-soap-migration`. Версия БД: **0**. Статус: **published**.

## Основание решения

В inputs названы WSDL и OpenAPI, но сами документы не приложены. Полный маппинг 14 операций невозможно составить по описанию.

Факты берутся из [снимка условия](00-task.md). Всё, что предлагается в [решении](02-solution.md), является проектным выбором; подтверждения недостающих фактов пока нет. Качество определяется соблюдением известных ограничений, объяснимыми компромиссами и способом проверки результата.

## Альтернативы и компромиссы

Адаптер уменьшает влияние изменения внешнего API на учёт, но требует хранения корреляций. Прямая переделка всех потребителей проще только при малом числе интеграций и полном совпадении смысла полей. Редкие операции можно исключать лишь после решения их владельца.

## Что может изменить рекомендацию

- Где доступны WSDL/XSD и OpenAPI с версиями, примерами запросов, ответов, ошибок и подписей? Ответ влияет на выбор: Нужны реальные контракты, а не выдуманные названия операций и полей.

- Как сейчас формируются «основание документа» и код подразделения: у нас или партнёром? Есть ли устойчивый ID для связи с REST-заявкой? Ответ влияет на выбор: Локальное обогащение возможно только при наличии достоверного источника и корреляции.

- Каковы бизнес-значение и обязательность всех операций, включая редкие и неиспользуемые? Есть ли сезонные вызовы? Ответ влияет на выбор: Низкая частота не доказывает возможность отключения.

- Есть ли у REST идемпотентность, запрос статуса, повторы webhook, порядок и идентификаторы событий? Ответ влияет на выбор: Асинхронный ответ 202 не является завершённой заявкой.

- Что означает параллельный прогон для операций с побочными эффектами? Есть ли sandbox или теневое сравнение без повторного создания? Ответ влияет на выбор: Дублирование продуктивных SOAP/REST-запросов может создать две заявки.

## Журнал решений

| Событие | Основание | Принятое решение | Статус |
|---|---|---|---|
| Снимок | Опубликованная задача версии 0 из локальной БД | Сохранить исходное условие без правок | Выполнено |
| Аудит полноты | Публичное условие и стартовые вкладки | Вынести недостающие факты и противоречия в отдельные вопросы | Выполнено |
| Подготовка эталона | Известные ограничения и незакрытые вопросы | Сохранить условный проект с альтернативами; не утверждать скрытые факты | Черновик |
| Уточнение у владельцев | Ответы пока отсутствуют | Обновить факты, рекомендацию, критерии и версию после получения ответов | Ожидается |

Журнал содержит проверяемые основания и решения. Он не является записью внутреннего потока мыслей. Обновления добавлять отдельными событиями с источником ответа.
