# Сервис уведомлений: каналы, предпочтения, дедупликация

Задача: `des-notifications`. Версия БД: **0**. Статус: **published**.

## Основание решения

«Доставляться обязательно» не определяет наблюдаемый результат и предел гарантии при недоступности каналов. Нужна согласованная семантика доставки и бюджета.

Факты берутся из [снимка условия](00-task.md). Всё, что предлагается в [решении](02-solution.md), является проектным выбором; подтверждения недостающих фактов пока нет. Качество определяется соблюдением известных ограничений, объяснимыми компромиссами и способом проверки результата.

## Альтернативы и компромиссы

Синхронный API подтверждает сохранение команды, асинхронное событие уменьшает связь с отправителем; оба требуют защиты промежутка между бизнес-событием и постановкой уведомления. Fallback увеличивает достижимость, но может повышать стоимость и число дублей.

## Что может изменить рекомендацию

- Что значит доставлено: провайдер принял, устройство получило, пользователь открыл или юридически уведомлён? Какой срок обязателен? Ответ влияет на выбор: Невозможно гарантировать чтение или доставку при недоступности всех каналов без отдельного процесса.

- Какие конкретно события обязательны, какие каналы разрешены и можно ли обходить тихие часы/предпочтения для каждого типа? Ответ влияет на выбор: Транзакционный тип сам по себе не задаёт все исключения.

- Какой бюджет SMS по периоду и что делать при его исчерпании для обязательного сообщения? Ответ влияет на выбор: Без приоритета между обязательностью и бюджетом правила могут быть несовместимы.

- Какие idempotency/status API и callbacks есть у провайдеров? Что делать при таймауте после возможного приёма? Ответ влияет на выбор: Слепой повтор и fallback могут отправить два сообщения.

## Журнал решений

| Событие | Основание | Принятое решение | Статус |
|---|---|---|---|
| Снимок | Опубликованная задача версии 0 из локальной БД | Сохранить исходное условие без правок | Выполнено |
| Аудит полноты | Публичное условие и стартовые вкладки | Вынести недостающие факты и противоречия в отдельные вопросы | Выполнено |
| Подготовка эталона | Известные ограничения и незакрытые вопросы | Сохранить условный проект с альтернативами; не утверждать скрытые факты | Черновик |
| Уточнение у владельцев | Ответы пока отсутствуют | Обновить факты, рекомендацию, критерии и версию после получения ответов | Ожидается |

Журнал содержит проверяемые основания и решения. Он не является записью внутреннего потока мыслей. Обновления добавлять отдельными событиями с источником ответа.
