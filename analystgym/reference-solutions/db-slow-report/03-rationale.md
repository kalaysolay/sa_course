# Отчёт по продажам собирается 40 минут: найти причину

Задача: `db-slow-report`. Версия БД: **0**. Статус: **published**.

## Основание решения

Условие достаточно для плана диагностики, но не для установленного диагноза и доказанного ускорения. Наличие DATE в фильтре — гипотеза, а не доказательство причины всех 40 минут.

Факты берутся из [снимка условия](00-task.md). Всё, что предлагается в [решении](02-solution.md), является проектным выбором; подтверждения недостающих фактов пока нет. Качество определяется соблюдением известных ограничений, объяснимыми компромиссами и способом проверки результата.

## Альтернативы и компромиссы

Индекс дешевле отдельной витрины по объёму изменений, но увеличивает стоимость записи и может не устранить основное ожидание. Реплика изолирует часть чтения при условии приемлемого лага. Агрегаты сокращают повторную работу, но требуют правил актуализации. Масштабирование обосновывается подтверждённым дефицитом ресурсов.

## Что может изменить рекомендацию

- Можно получить полный SQL с обоими подзапросами и реальными значениями параметров? Ответ влияет на выбор: Упрощённого пересказа недостаточно для проверки повторных сканирований, JOIN и корректности переписывания.

- Как выглядят DDL orders, order_items, products, stores: типы, PK/FK, все индексы, партиции и ограничения? Ответ влияет на выбор: Индекс только по order_items не описывает доступ к orders; тип created_at влияет на границы дат.

- Есть ли план выполнения с фактическими строками, временем и буферами для медленного запуска? Где его безопасно получить? Ответ влияет на выбор: Нужно отличить плохие оценки, чтение диска, сортировки и многократные выполнения; диагностический запуск тоже создаёт нагрузку.

- Что происходило с CPU, RAM, дисковыми задержками/IOPS, свободным местом, сетью, блокировками и активными сессиями в 06:00? Есть ли лимиты контейнера? Ответ влияет на выбор: Позволяет проверить инфраструктурную причину. Фраза «с инфраструктурой всё хорошо» без временного интервала и метрик не исключает её.

- В эти 40 минут входят ожидание очереди, SQL, передача результата, генерация Excel и отправка? Есть разбивка по этапам? Ответ влияет на выбор: Ускорение SQL не решит задержку, если основное время тратится на выгрузку или ожидание.

- В каком часовом поясе определены «вчера» и прошлая неделя? Какие статусы, отмены, возвраты и скидки входят в выручку? Ответ влияет на выбор: Границы полуинтервала и эквивалентность результата нельзя определить только по имени created_at.

|---|---|---|---|
| Снимок | Опубликованная задача версии 0 из локальной БД | Сохранить исходное условие без правок | Выполнено |
| Аудит полноты | Публичное условие и стартовые вкладки | Вынести недостающие факты и противоречия в отдельные вопросы | Выполнено |
