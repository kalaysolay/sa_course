# Продажи против рисков: конфликт требований и решение аналитика

Задача: `req-stakeholder-conflict`. Версия БД: **0**. Статус: **published**.

Снимок: `../snapshot.json`, поле `tasks`, поиск по ID. Это исходные данные, а не предложенные дополнения.

## Кратко

Коммерческий директор требует упростить скоринг, риск-менеджер запрещает. Релиз через три недели. Что делает аналитик?

## Контекст

- Онлайн-банк выдаёт кредиты физлицам. Сейчас при заявке клиент заполняет 14 полей, скоринг проверяет доходы через два внешних источника и запрашивает дополнительные документы у 30% заявителей. Конверсия в выдачу — 41%, среднее время решения — 22 минуты.
- Коммерческий директор: «Конкуренты выдают за 5 минут по трём полям. Мы теряем рынок. Уберите лишние поля и документы, решение — мгновенно».
- Директор по рискам: «Любое ослабление скоринга = рост NPL. Мы не подпишем изменения без данных о влиянии на портфель. И требования регулятора по оценке платёжеспособности никто не отменял».
- Оба руководителя настаивают, оба подчиняются председателю правления. Релиз маркетинговой кампании «Быстрый кредит» запланирован через три недели, бюджет на рекламу уже согласован.

## Цель

Как аналитик: разобрать конфликт, собрать данные, найти варианты решения, которые удовлетворяют обе стороны (или честно показать компромисс), и подготовить решение для правления с оценкой эффекта и рисков.

## Исходные данные

- Данные за 6 месяцев: конверсия по шагам воронки, время заполнения заявки, доля отказов на каждом шаге, статистика запроса документов, NPL по сегментам и по источникам данных.
- Регуляторные требования: обязательная оценка платёжеспособности, требования к хранению данных и к идентификации, лимиты по суммам.
- Возможности: есть данные из бюро кредитных историй, есть доступ к данным о зарплатных клиентах, есть поведенческая аналитика в форме заявки.
- Ограничения: 3 недели до кампании, команда разработки занята на 60% другими задачами.

## Ограничения

- Нарушать регуляторные требования нельзя: это риск отзыва лицензии.
- Релиз кампании через три недели: нужно решение, которое можно внедрить хотя бы частично.
- Аналитик не принимает бизнес-решение сам, но обязан подготовить его так, чтобы решение было обоснованным.

## Ожидаемые результаты

- Карта стейкхолдеров: кто участвует, какие у них цели и метрики, где конфликт интересов, кто принимает решение.
- Разбор требований обеих сторон: что стоит за «уберите поля» и «нельзя ослаблять» (задачи, а не позиции).
- Данные, которые нужны для решения: какие гипотезы проверяем, откуда берём цифры, как считаем эффект.
- Варианты решения (минимум три) с оценкой влияния на конверсию, риски, сроки и стоимость; рекомендация с обоснованием.
- План проверки решения: пилот/A-B, метрики, критерии остановки, как масштабируем.
- Решение для регуляторных ограничений: что нельзя менять ни при каких условиях и как это объяснить коммерческому директору.
- План коммуникации: как и кому презентуем, что делаем при несогласии одной из сторон.
