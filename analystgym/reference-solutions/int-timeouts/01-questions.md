# Нестабильный внешний сервис: таймауты и повторные попытки

Задача: `int-timeouts`. Версия БД: **0**. Статус: **published**.

## Вывод по полноте

Есть предел 5 секунд и неидемпотентность POST, но отсутствуют данные для выбора конкретных таймаутов и безопасных повторов.

## Открытые вопросы

Для каждого вопроса нужны ответ, источник и решение: дополнить условие / оставить частью задания / разрешить явное допущение. Ответы пока не получены.

### int-timeouts-Q01 · P0 · Правило

**Вопрос пользователя:** Повторная запись проверки у провайдера только технический дубль или дополнительная плата, юридическое действие либо иной бизнес-эффект?

**Зачем нужен ответ:** Определяет, допустим ли повтор после неизвестного исхода. Одинаковый вердикт не делает POST безопасным.

**Предлагаемый адресат:** Владелец интеграции. **Статус:** открыт.

### int-timeouts-Q02 · P0 · Данные

**Вопрос пользователя:** Можно ли узнать результат ранее отправленной проверки по ID заявки/проверки, через callback или выгрузку?

**Зачем нужен ответ:** Без этого неизвестный исход нельзя автоматически разрешить надёжно.

**Предлагаемый адресат:** Владелец провайдера. **Статус:** открыт.

### int-timeouts-Q03 · P0 · Правило

**Вопрос пользователя:** Можно ли сохранить заявку как ожидающую проверку? Какие действия запрещены до вердикта и когда требуется ручная обработка?

**Зачем нужен ответ:** Нужно определить судьбу заявки при недоступности проверки.

**Предлагаемый адресат:** Бизнес / риск-служба. **Статус:** открыт.

### int-timeouts-Q04 · P0 · Данные

**Вопрос пользователя:** Как распределены connect/read/полное время по процентилям и ошибкам? Пять секунд включают нашу обработку, сеть и сохранение заявки?

**Зачем нужен ответ:** Конкретные бюджеты должны укладываться в общий дедлайн, а не складываться сверх него.

**Предлагаемый адресат:** Эксплуатация. **Статус:** открыт.
