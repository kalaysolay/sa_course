# Контракт API для мобильного приложения: версии, пагинация, ошибки

Задача: `req-api-contract`. Версия БД: **0**. Статус: **published**.

## Основание решения

Для проектного контракта данных достаточно, но отсутствуют реальные типы операций, текущие клиенты и согласованные НФТ. Пример должен явно отделять предложенные поля от фактов.

Факты берутся из [снимка условия](00-task.md). Всё, что предлагается в [решении](02-solution.md), является проектным выбором; подтверждения недостающих фактов пока нет. Качество определяется соблюдением известных ограничений, объяснимыми компромиссами и способом проверки результата.

## Альтернативы и компромиссы

Cursor удобен при длинной меняющейся истории, offset проще при небольшом стабильном наборе; выбор зависит от требований согласованности. Версия в URL или заголовке допустима при общей политике поддержки. Общий API не обязан игнорировать особенности мобильной сети.

## Что может изменить рекомендацию

- Есть ли текущая OpenAPI/примеры ответов и матрица поддерживаемых версий приложений с их зависимостями от полей/enum? Ответ влияет на выбор: Нельзя доказать совместимость, не зная существующих клиентов.

- Какие типы и статусы операций существуют, какие поля общие/условные и как трактуются null, отсутствие и неизвестный enum? Ответ влияет на выбор: Определяет стабильную схему и поведение старых клиентов.

- Есть ли общий устойчивый ID операции в трёх источниках, единая дата сортировки и способ объединения дублей/исправлений? Ответ влияет на выбор: Нужен контракт идентичности и порядка выдачи.

- При недоступности одного источника возвращать частичный список с пометкой или целиком ошибку? Какая допустимая свежесть? Ответ влияет на выбор: Нельзя скрыто выдавать неполную финансовую историю за полный результат.

## Журнал решений

| Событие | Основание | Принятое решение | Статус |
|---|---|---|---|
| Снимок | Опубликованная задача версии 0 из локальной БД | Сохранить исходное условие без правок | Выполнено |
| Аудит полноты | Публичное условие и стартовые вкладки | Вынести недостающие факты и противоречия в отдельные вопросы | Выполнено |
| Подготовка эталона | Известные ограничения и незакрытые вопросы | Сохранить условный проект с альтернативами; не утверждать скрытые факты | Черновик |
| Уточнение у владельцев | Ответы пока отсутствуют | Обновить факты, рекомендацию, критерии и версию после получения ответов | Ожидается |

Журнал содержит проверяемые основания и решения. Он не является записью внутреннего потока мыслей. Обновления добавлять отдельными событиями с источником ответа.
