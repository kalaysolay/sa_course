# Контроль качества ревью

Статус: качество настоящей LLM **не откалибровано методистом**. Ни unit-тесты,
ни HTTP-стаб не доказывают качество её суждений. В интерфейсе это обозначено.
Владелец подтвердил отсутствие готовых разборов 2026-10-17.

Контрольный набор:
`backend/modules/review/src/test/resources/review-control-set.json`.
Пять решений одной задачи: развёрнутое, слабое, противоречивое, термины,
инъекция инструкций. Поле `methodist` пока null; категории — описание примера,
не готовая экспертная оценка. Mock-регрессия запрещает высокий балл всем пяти.

Для сравнения методист независимо размечает все критерии каждого примера,
задаёт допустимый диапазон балла и пояснение. Файл разметки: объект по ID
примеров, значения с `reviewer`, `reviewedAt`, `reason`, `states` (id критерия →
hit/partial/miss), `minScore`, `maxScore`. Подпись reviewer — атрибуция файла,
не электронная подпись и не серверная проверка полномочий.

Файл результатов — объект по ID примеров: `criteria` и `grade` из реального
ревью, `context` с `taskVersion`, `promptVersions`, `model`. Для каждой пары
промптов/модели делать отдельный отчёт; сохранять исходные запросы и ответы
из журнала. Повторы учитывать отдельно, не выбирать только удачный ответ.

Из tasks-mockup:

```sh
node scripts/compare-review-eval.cjs ../backend/modules/review/src/test/resources/review-control-set.json responses.json annotations.json
```

Отчёт показывает несовпадения состояний и выход за экспертный диапазон.
Неполный контекст/разметка — `incomplete`, ненулевой код завершения.
Совпадение пяти примеров — регрессия данного набора, не статистическая
гарантия. Перед утверждениями о качестве нужны расширение набора и независимые
разборы методиста. Инструмент не отправляет запросы модели и не тратит токены.
