# AnalystGYM — кликабельная редакторская

Отдельный локальный HTML-макет. Не подключён к API приложения, не меняет реальные курсы и не исполняет HTTP/SQL. Каждый экран — отдельный HTML-файл; общий JavaScript и CSS переиспользуются.

Открыть `index.html` в браузере. Для одинакового хранения данных между страницами рекомендуется локальный HTTP:

```powershell
node D:/Projects/sa_course/analystgym/admin-mockup/server.mjs
```

Адрес: http://127.0.0.1:5191. Сервер слушает только loopback. Зависимостей для установки нет. На Windows можно запустить `start.bat` двойным кликом и открыть этот адрес в браузере.

Проверка и пересборка HTML: `node build.mjs` из этого каталога. Команда проверяет синтаксис общего JS и создаёт 24 отдельных HTML-экрана. Изменения приложения за пределами этого каталога не нужны.

## Проходы

1. **Новый курс:** Все курсы → Создать курс → заполнить название/описание → Добавить модуль → Добавить урок → наполнить лекцию.
2. **Настройки:** Программа → Настройки курса; у модуля — «Настроить», у урока — «Настройки урока».
3. **Лекция:** Добавить блок → заголовок / текст / таблица / акцент. Редактор текста поддерживает базовые Markdown-маркеры жирного, курсива и ссылки. Стрелки меняют порядок блоков.
4. **Встроенная активность:** Добавить блок → Тест или Практика → сохранить. Активность появляется между блоками и в соответствующем разделе урока.
5. **Тесты:** вкладка Тесты → Добавить тест → вопросы с одним/несколькими правильными ответами, объяснения, порог. Можно добавлять/удалять вопросы и варианты. Сохранение проверяет заполненность.
6. **Практика:** вкладка Практика → тип → сценарий → условие, стартовая рабочая область, шаги, ожидаемый результат. HTTP/SQL проработаны подробнее; SOAP/Kafka/очереди показывают концепцию формы, а не готовые сценарии исполнения.
7. **JSON:** справа в редакторе практики. Поля собираются в JSON; ручные изменения применяются кнопкой. Неизвестные поля, ресурсы и политики отклоняются. Это демонстрация контракта, не окончательная JSON Schema.
8. **Переиспользование:** Из библиотеки → Добавить в урок. Общая практика остаётся в библиотеке после удаления привязки. Редактирование общей практики меняет её во всех использующих уроках; показывается предупреждение.
9. **Порядок:** Программа → Порядок уроков. Стрелки и drag-and-drop переставляют уроки, select переносит между модулями. Стрелки модулей меняют порядок модулей. «Сохранить порядок» фиксирует изменения.
10. **Материалы:** ссылка, файл (сохраняется только имя), шаблон артефакта. Для шаблона — создание / продолжение / доработка и общий ключ артефакта.
11. **Предпросмотр:** верхняя правая навигация урока → Предпросмотр. Тесты проверяются локально. HTTP/SQL показывают явно помеченные статические демо-результаты, не вычисленные ответы на введённый код.
12. **Публикация:** Программа → Публикация. Проверяются название/описание, наличие уроков в модулях и блоков в лекциях. Публикуется только демо-статус в localStorage. Это не реализация серверного workflow и не публикация в интернете.
13. **Удаление:** отдельная страница подтверждения для модуля, урока, теста или материала. Удаление теста очищает его вставки в лекции. Удаление практики из урока убирает вставки, сохраняя общую практику.
14. **Копирование:** Настройки урока → Создать копию. Содержание и тесты копируются, общие тренажёры переиспользуются.

## Навигация и хранение

Структура: Курс → Модуль → Урок → Лекция / Тесты / Практика / Материалы. Справа сверху в уроке — предыдущий/следующий урок и предпросмотр; ниже — четыре вкладки.

Пример курса наполнен HTTP/REST и SQL. Новый курс начинает с пустой программы. Сохранение — явными кнопками; незавершённые формы предупреждают об уходе. Порядок блоков и привязки сохраняются сразу, порядок уроков — отдельной кнопкой.

Ключ localStorage: `analystgym:admin-prototype:v1`. Для восстановления примера используйте «Сбросить демо-данные» в левой панели и подтвердите действие на отдельной странице. Разные браузеры, file:// и HTTP имеют раздельное хранение.

## Ограничения

Нет настоящей аутентификации, загрузки/скачивания файлов, серверных версий, разграничения ролей, реального исполнения лабораторий и проверок результатов практики. Редактор помогает обсудить пользовательские сценарии до разработки. Прототип не содержит production-секретов.

## Выполненная проверка

Все 24 HTML-экрана открыты в браузере; ошибок JavaScript в журнале нет. Проверены создание курса с пустой программой, модуля, урока и блока, перенос урока между модулями, сохранение теста и HTTP/SQL-практики, применение JSON, добавление шаблона артефакта, вставка теста в лекцию, правильный ответ с объяснением, демонстрационный ответ API, изменение демо-статуса публикации и восстановление исходного примера.

На ширине 1440 проверены верхняя правая навигация урока и положение вкладок под ней; горизонтального переполнения на 24 экранах нет. Также просмотрен узкий экран встроенного браузера. Синтаксическая проверка и сборка `node build.mjs` завершились успешно. Основной backend не менялся и для этого независимого статического макета не собирался.
