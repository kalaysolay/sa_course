## Usable Teaching Points

1. An analytical artifact is a fixed trace of understanding: a note, list, diagram, requirement, model, contract or specification that helps people align.
2. An artifact is valuable when it answers a practical team question, not merely because it exists as a file.
3. Early artifacts can be lightweight: first-day notes, problem statement, open questions, stakeholder list, glossary.
4. Middle-path artifacts translate business context into work for the team: scenarios, requirements, acceptance criteria, process diagrams and interaction diagrams.
5. Later artifacts describe system detail: data model, data dictionary, API contracts, permissions, integrations and consistency checks.
6. Artifacts reduce ambiguity by making decisions, assumptions, terms and open questions visible.
7. Lesson 8 closes module 1: learners should leave with a map of the profession, the analyst work cycle, the BA/SA path and the artifact landscape.
