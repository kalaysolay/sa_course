## Предупреждения автору

Одна область, простые состояния, внешние события; history/composite/orthogonal не вводить. Не переносить упрощённое 'одно состояние за раз' на все UML state machines. Различать событие 'получен комментарий' и условие 'полномочие есть'. Наличие true guard не означает автоматического перехода без соответствующего события. Не обещать, что подпись с одним guard без trigger непрерывно опрашивает условие.

Закрыто в нашем примере — обычное состояние с разрешённым обратным переходом. FinalState не имеет исходящих transitions и не означает удаление записи из БД. Выход из Закрыто при повторном открытии демонстрировать настоящей стрелкой, а не описывать только словами. Не утверждать, что повторное событие автоматически безопасно/идемпотентно. Внешняя петля запускает exit/entry повторно, даже если имя активного состояния прежнее. Внутренняя обработка полезна для комментария без пере-входа — показать явно внутри state box, а не рисовать внешнюю петлю и объяснять как internal.

Схемы: реальные symbols при первом объяснении, увеличенная подпись `trigger [guard] / effect`, маленькая растущая модель обращения и 2–3 walkthrough. Final и initial — разные изображения. Никаких flow-final/cross или activity merge из предыдущего урока. Короткие заголовки, текст9–13k, убрать декоративную терминологию.
