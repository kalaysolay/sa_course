# Независимая содержательная проверка v1

Проверены объявленные brief, source pack, draft-v1, course-style и исходный XML пяти SVG. Канонические материалы проекта и историческая спецификация не открывались. Это содержательная проверка и сверка графа/подписей; фактический рендер и визуальную читаемость проверяет оркестратор отдельно. Успешную отрисовку этот отчёт не удостоверяет.

## Семантика и маршруты

- Один объект, четыре обычных состояния: draft-v1.md:5–7; request-lifecycle.svg содержит «Новое», «В работе», «Ожидает уточнения», «Закрыто». Начальная стрелка ведёт в «Новое» без trigger/guard.
- Обычный путь вручную: initial → Новое → назначено → В работе → решение подтверждено при записанном основании → Закрыто, эффект «уведомить сотрудника». Текст: строка 43; направления и подписи основной схемы совпадают.
- Путь с уточнением вручную: Новое → назначено → В работе → уточнение запрошено / отправить запрос → Ожидает уточнения → уточнение получено / сохранить ответ → В работе → решение подтверждено [основание записано] / уведомить сотрудника → Закрыто. Текст: 39–45 и 93. Автоматического закрытия по получению ответа нет.
- Guard не запускает переход сам: три случая в строке 33 явно различают true без события, событие с false и событие с true. Последующая запись основания не заменяет новое подтверждение.
- Открытие вручную: в Закрыто событие «повторное открытие запрошено» с полномочием И основанием ведёт в В работе с регистрацией открытия; без полномочия состояние остаётся Закрыто, регистрации нет (49–51, 95). Обратная стрелка действительно есть. Закрыто нарисовано обычным состоянием; FinalState отдельно на notation.svg, без исходящего перехода. Удаление записи из final не выводится (53–55).
- Entry/exit: текст 63–69 и верхняя схема entry-exit-loop.svg совпадают для запроса уточнения: остановить отсчёт → отправить запрос → включить напоминание. Обратный путь опирается на основной граф и показанные действия состояний: выключить напоминание → сохранить ответ → начать отсчёт.
- Внешняя петля действительно выходит и возвращается в тот же прямоугольник; внутренняя обработка записана внутри состояния, без стрелки. Для двух комментариев после первого входа: внешняя — entry=3, exit=2, сохранение=2; внутренняя — entry=1, exit=0, сохранение=2. Это соответствует строкам 75–79.
- Повторное подтверждение в Закрыто: подходящего перехода нет; состояние прежнее. Строка 81 не объявляет это обязательной API-ошибкой и не обещает идемпотентности уведомления.
- Diagnostics вручную: initial ведёт в В работе; из Ожидает уточнения есть только исходящая стрелка обратно. Из initial пути в Ожидает уточнения нет. Добавление указанной стрелки запроса делает узел достижимым. Это соответствует строке 87 и diagnostics.svg. Пересечение guards и отсутствие выхода как неоднозначный признак разобраны в 89–91.

## Покрытие и ясность

LO1: 5–15 — граница одного объекта, состояние/действие/activity. LO2: 9–25, 53–55 и notation.svg — реальные символы, направление, построение фрагмента, initial/final. LO3: 27–35 и transition-label.svg — trigger/guard/effect с тремя случаями. LO4: 49–57 — разрешённое и запрещённое открытие, обычное Закрыто. LO5: 63–69 — действия и порядок. LO6: 73–81 — петля, внутренняя обработка, повторное событие и подсчёт. LO7: 87–97 — недостижимость, пропущенное событие, условия, наблюдаемый сценарий и отрицательные случаи. Все семь LO раскрыты объяснениями и конкретными действиями, а не одним упоминанием термина.

Риски урока 20 закрыты содержательно: короткие предметные заголовки; единый кейс вместо повторных общих вступлений; реальные образцы четырёх основных знаков; явно показанные состояния и петля; подписи событий/условий/эффектов совпадают с проходами. Новая идея объясняется через конкретное обращение. Отсутствующие авторские материалы прямо обозначены, учебные правила не выданы за согласованные требования.
