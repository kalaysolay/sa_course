# Независимая содержательная проверка UML-ACTIVITY

Ревью прочитало объявленные brief, source pack, draft-v1 и course style. Внешнее исследование повторно не выполнялось.

## Проверенные маршруты

- Линейный путь: подготовка и отправка сотрудником → проверка и регистрация системой → рассмотрение и решение офицером → уведомление системой → конец. Дорожки обозначают ответственность, а не отдельные потоки.
- Сведений достаточно: initial → верхний merge → подготовка/отправка → проверка → guard [да] → регистрация → рассмотрение → решение → уведомление → activity final. Уточнение не выполняется.
- Одно уточнение: первая проверка → guard [нет] → системное сообщение → верхний merge → сотрудник уточняет/отправляет → новая проверка → [да] → общий успешный путь. Текст не сохраняет старый результат проверки и не регистрирует до выхода из цикла.
- Бесконечный повтор не маскируется: отмена, отказ, таймаут и достаточность сведений оставлены вопросами владельцу процесса; произвольного лимита попыток нет.
- Fork: обе независимые проверки заканчиваются заключениями, включая отрицательные. Стандартный AND-join ждёт оба входа; ранняя ветвь ожидает позднюю. Обещания физически одновременной работы нет.
- Контрпример decision→join: выбранный путь приходит к join, невыбранный никогда не запускается. Причина невозможности продолжения объяснена. Исправление выбирается по смыслу: merge для альтернатив или fork/join для двух обязательных проверок.
- Flow final/activity final: две отдельные мини-иллюстрации честно названы фрагментами, а не полной двухпоточной схемой. В мысленном двухпоточном случае окончание напоминания через flow final сохраняет рассмотрение; activity final завершает рассматриваемую активность. Предупреждение об уничтоженном входе перед join корректно.

## Проверенные объяснения

Guards не трактуются как проверяемые сверху вниз; else описан как остаточный путь. Входы первого и повторного проходов объединяются merge. Action не подменён состоянием/объектом; control flow не объявлен передачей файла или данных. Object flow описан отдельно. Различия use case/activity/state/sequence/BPMN ограничены назначением. Примеры и правила Compliance явно учебные; неизвестное не превращается в согласованное правило. Есть практические вопросы при ответах «всегда по-разному» и «рисуйте сами».

Итог: critical/major/minor замечаний не обнаружено. Обе перспективы APPROVED; rewrite не требуется. Рендер пяти схем отдельно проверен оркестратором.
