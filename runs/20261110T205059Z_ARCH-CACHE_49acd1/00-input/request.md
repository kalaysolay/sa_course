# Запрос автора: перегенерация урока ARCH-CACHE (order 30)

## Особые указания автора (11.11.2026)

- Особое внимание — качеству и понятности материала.
- Лекцию читают **не погружённые** в тему люди: каждому новому термину нужно доходчивое объяснение при первом же использовании.
- Разрешены (и приветствуются) понятные бытовые аналогии с обязательной границей применимости (в духе course-style.md).
- Тема идёт сразу за уроком 29 (API Gateway — обзор), где gateway упомянут вместе с кэшированием как «мост к следующему уроку» — использовать этот мост как вход и не пересказывать gateway-урок.
- Сквозной кейс — проект Compliance: в лекции должно быть применение, а не только упоминание.
- Приоритет исследований — первичные официальные источники (nginx content caching docs, Redis docs, AWS docs, RFC 9111 HTTP caching); проверять фактическую доступность ссылок и фиксировать evidence в source pack.
- Целевой уровень: базовый обзор (не энциклопедия). Ясность важнее полноты. Негативные случаи обязательны (устаревший кэш, кэш ради кэша).
