# Запрос автора: перегенерация урока ARCH-SYNC (order 32)

## Особые указания автора (11.11.2026)

- Особое внимание — качеству и понятности материала.
- Лекцию читают **не погружённые** в тему люди: каждому новому термину нужно доходчивое объяснение при первом же использовании.
- Разрешены (и приветствуются) понятные бытовые аналогии с обязательной границей применимости (в духе course-style.md).
- Тема открывает новый раздел M05-S04 «Взаимодействие» и идёт после урока 31 (хранилище). Взаимодействие — первый раз, когда в курсе разбираются отношения компонентов между собой: объяснять через уже знакомое (шлюз из урока 29, сервисы из урока 27, хранилище из урока 31).
- Сквозной кейс — проект Compliance: в лекции должно быть применение, а не только упоминание.
- Приоритет исследований — первичные официальные источники (RFC 9110 HTTP Semantics, gRPC core concepts, AWS Builders' Library про таймауты и ретраи, Azure Architecture Center Retry pattern); проверять фактическую доступность ссылок и фиксировать evidence в source pack.
- Целевой уровень: базовый обзор (не энциклопедия). Ясность важнее полноты. Обязательны негативные случаи: пользователь ждёт слишком долго, каскад таймаутов, повторные попытки превращаются в «шторм», «залипший» вызов блокирует остальных.
