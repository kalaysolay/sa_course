## A1. Что такое API Gateway

**Выберите один вариант.** Что такое API Gateway и где он стоит на схеме системы?

- **A.** Единая точка входа для всех обращений к API: по правилам определяет, кто обратился, что ему разрешено, куда передать запрос и в каком виде вернуть ответ. На схеме он стоит между клиентами и внутренними сервисами.
- **B.** Компонент, который заменяет внутренние сервисы: после его введения сервисы обращений и справочников больше не нужны.
- **C.** Библиотека или модуль, который внешняя организация встраивает в свою программу, чтобы обращаться к API Compliance.
- **D.** Отдельный вход для сотрудников портала, а внешние интеграторы подключаются к каждому внутреннему сервису напрямую.

## A2. Gateway и reverse proxy

**Выберите один вариант.** Какое утверждение о связи reverse proxy (урок 28) и API Gateway верно?

- **A.** Это разные механизмы без общего устройства: reverse proxy просто «передаёт запрос на указанный сервер и возвращает ответ», а gateway — самостоятельный слой со своей логикой; общего у них только то, что оба стоят на входе.
- **B.** Gateway — это «умный» reverse proxy, поэтому любой backend — даже монолит без внешних клиентов — обязан его иметь, иначе вход в систему спроектирован неправильно.
- **C.** Один и тот же продукт может исполнять обе роли: reverse proxy, к которому добавили правила и настройку (ключи и токены, лимиты и квоты, несколько версий API), становится gateway; роль определяется количеством правил на входе, а не названием коробки.
- **D.** Reverse proxy и gateway — синонимы: это два названия одной роли, и различий в обязанностях между ними нет.

## A3. Перегрузка от интегратора

**Выберите один вариант.** Интегратор по ошибке запустил бесконечный цикл: его программа шлёт в Compliance сотни запросов в секунду, и сотрудники портала жалуются на медленную работу. Какая обязанность gateway решает эту проблему и почему именно она?

- **A.** Лимиты и квоты: они делят возможности системы между клиентами справедливо и предсказуемо, поэтому один клиент с ошибкой в программе не тормозит работу остальных — включая сотрудников портала.
- **B.** Маршрутизация: поток рассредоточится по разным сервисам, и ни один из них не перегрузится.
- **C.** Агрегация: шлюз склеит ответы нескольких сервисов в один, и интегратору станет нужно меньше запросов.
- **D.** Мониторинг: шлюз зафиксирует источник лишнего трафика и сам остановит его.

## A4. Почему правила живут на входе

**Короткий ответ.** Почему общие правила для всех клиентов — проверка ключей и токенов, лимиты по клиентам, единые логи — размещают один раз на gateway, а не повторяют в каждом внутреннем сервисе? Ответьте своими словами, в 3–5 предложениях.

## A5. Когда gateway избыточен

**Выберите один вариант.** Ранняя стадия Compliance: система только для сотрудников, один веб-портал, один монолитный backend. Правила доступа просты и одинаковы для всех, версионности API нет, лимитов по клиентам нет, учёт запросов сервис ведёт сам. Какое решение правильное и почему?

- **A.** Достаточно reverse proxy с балансировкой из урока 28: шлюз не решает ни одной задачи этой системы, а цену платят сразу и полностью — новые правила, настройка и лишняя точка отказа.
- **B.** Gateway нужен: это «умный» reverse proxy, и без него вход в систему спроектирован неправильно.
- **C.** Gateway стоит поставить заранее, «на вырост»: тогда при появлении внешних интеграторов ничего не придётся переделывать.
- **D.** Правила доступа лучше продублировать в каждом модуле монолита, чтобы система не зависела от одного компонента на входе.

## A6. Читаем требования: есть ли запрос на gateway

**Короткий ответ.** Аналитик читает фрагмент требований к Compliance:

> 1. «Система должна обеспечивать единый вход для всех внешних обращений к API».
> 2. «Система выдаёт API-ключи интеграторам и проверяет их при каждом обращении».
> 3. «Для каждого интегратора задаются собственные лимиты и квоты».
> 4. «Сервис справочников хранит данные справочников и предоставляет их по запросу».
> 5. «API должен поддерживать одновременную работу двух версий: v1 и v2».

Определите для каждого пункта, является ли он признаком запроса на API Gateway («да/нет»), и одной фразой объясните почему.

## A7. Позиция на схеме

**Короткий ответ.** На сквозной схеме Compliance gateway стоит между клиентами (веб-портал, внешние интеграторы) и внутренними сервисами (обращения, справочники, отчёты). Объясните, почему он стоит именно на входе, а не отдельным блоком рядом с сервисами. Что это даёт клиентам и что это меняет для сервисов? Ответьте в 4–6 предложениях.

## A8. Мини-кейс: единый вход в API Compliance

Вы — аналитик рабочей группы Compliance. Решение: API системы открывается наружу, и все клиенты — веб-портал и внешние интеграторы — работают через единый вход.

Подготовьте фрагмент проектного решения:

1. Опишите словами или схемой (например, mermaid flowchart), как выглядит сквозной путь обращения к API: клиенты → gateway → внутренние сервисы (обращения, справочники, отчёты). Прямых обращений клиентов к сервисам быть не должно.
2. Распределите по слоям, где «живут»: выдача и проверка ключей и токенов; лимиты и квоты для каждого клиента; маршрутизация по путям `/api/requests`, `/api/reports`, `/api/directories`; единые логи и метрики. Для каждого элемента укажите одной фразой, почему он живёт именно здесь.
3. Обоснуйте в 3–5 предложениях решение «gateway, а не только reverse proxy» по признакам из лекции и назовите цену, которую за это решение платят.
