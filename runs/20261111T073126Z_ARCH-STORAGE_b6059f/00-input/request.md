# Запрос автора: перегенерация урока ARCH-STORAGE (order 31)

## Особые указания автора (11.11.2026)

- Особое внимание — качеству и понятности материала.
- Лекцию читают **не погружённые** в тему люди: каждому новому термину нужно доходчивое объяснение при первом же использовании.
- Разрешены (и приветствуются) понятные бытовые аналогии с обязательной границей применимости (в духе course-style.md).
- Тема идёт сразу за уроком 30 (Кэш — обзор), где прозвучал мост: «копия всегда указывает на оригинал, а оригиналы лежат в хранилищах — базы, файловые системы, объектные хранилища». Использовать этот мост как вход; кэш-урок не пересказывать.
- Сквозной кейс — проект Compliance: в лекции должно быть применение (заявления, доказательства, вложения, фотографии подарков), а не только упоминание.
- Приоритет исследований — первичные официальные источники (AWS S3 docs, Microsoft Learn Azure Blob Storage, Google Cloud Storage docs, AWS EBS/docs для разграничения блочного хранилища); проверять фактическую доступность ссылок и фиксировать evidence в source pack.
- Целевой уровень: базовый обзор (не энциклопедия). Ясность важнее полноты. Обязательны негативные случаи (почему нельзя «просто положить в S3 папку», риски «неограниченного» объектного хранилища, цена ошибки в выборе типа хранилища).
