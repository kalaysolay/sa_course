# Скилл: написать лекцию (write-lesson)

## Назначение

Создать цельную лекцию по утверждённому Lesson Brief для начинающего аналитика.

## Обязательные входы

- `lesson-brief.json` (или `01-brief/lesson-brief-final.json`);
- `source-pack.md`;
- `course/audience.md` / копия в run;
- `course/course-style.md` / копия в run;
- контекст сквозного проекта Compliance.

## Порядок работы

1. Построй внутренний narrative outline: знакомая ситуация, смысл темы, понятие, пример, практический вывод.
2. Введи термин только после объяснения, какую проблему он помогает увидеть или решить.
3. Используй абзацы и единый сценарий как основную форму. Списки — для независимых пунктов и кратких итогов.
4. Не ставь несколько списков или таблиц подряд. Если материал похож на конспект — перепиши в прозу до ревью.
5. Таблицы, чеклисты и плотные перечисления по возможности уводи в практику, ответы, project task или короткий финальный recap.
6. Для сложной технической абстракции добавь уместную аналогию и сразу обозначь, где она перестаёт быть точной.
7. Для архитектуры, интеграций, API, БД, инфраструктуры, компонентов, сервисов, очередей, событий, маршрутов или деплоя добавь хотя бы одну визуальную модель (Mermaid или другая Markdown-схема).
8. Перед технической записью (URL, endpoint, route, queue/topic, service, table, port, `domain/api/resource -> service`) объясни видимые части для новичка.
9. Свяжи объяснение с Compliance, не выдумывая фактов проекта.
10. Если использовал источники — заверши разделом `## Использованные источники` с кликабельными ссылками только на реально использованные.
11. Проверь покрытие `mustCover`, learning outcomes, границ `doNotCover` и читабельность для новичка.

## Результат

`03-lecture/draft-vN.md` (после одобрения ревью — `03-lecture/final.md`)

## Запрещено

- менять Lesson Brief или project state;
- выдавать draft за approved;
- заменять объяснение таблицей, набором bullets или перечнем терминов;
- сдавать лекцию, которая при беглом просмотре выглядит как список тезисов;
- использовать аналогию как доказательство технического решения;
- показывать URL, endpoint, маршрут, очередь, событие, service mapping или таблицу без схемы и расшифровки.
