# Ответы и ориентиры к практике урока 13

## Задание 1

Сотрудник должен иметь возможность создать обращение - функциональное.

Список обращений должен открываться не дольше 2 секунд при 500 активных обращениях - нефункциональное, производительность.

Офицер должен иметь возможность запросить уточнение - функциональное.

Пользователь без роли офицера не должен видеть внутренние комментарии - нефункциональное ограничение безопасности/доступа, хотя связано с поведением системы.

Дашборд руководителя должен обновляться не реже одного раза в 15 минут - нефункциональное, актуальность данных.

Система должна сохранять историю изменения статусов - функциональное требование, к которому можно добавить нефункциональные ограничения по сроку хранения и доступу.

## Задание 2

Примеры:

- форма регистрации подарка должна открываться не дольше 2 секунд при нормальной нагрузке;
- данные о подарке должны быть доступны только сотруднику, комплаенс-офицеру и ролям, которым это разрешено;
- система должна сохранять историю изменения статуса регистрации подарка не менее 5 лет;
- обязательные поля должны показывать понятные сообщения об ошибке рядом с полем;
- вложения к регистрации подарка должны иметь ограничение по размеру и допустимым типам файлов.

## Задание 3

Система должна быть быстрой: "Список обращений должен открываться не дольше 2 секунд при 500 активных обращениях для пользователя с ролью комплаенс-офицера".

Система должна быть безопасной: "Пользователь без роли комплаенс-офицера не должен получать доступ к внутренним комментариям обращения ни через интерфейс, ни через API".

Интерфейс должен быть удобным: "Если обязательное поле не заполнено, форма должна показать сообщение рядом с этим полем и не отправлять данные до исправления ошибки".

Отчет должен быть актуальным: "Данные на дашборде руководителя должны обновляться не реже одного раза в 15 минут".

## Задание 4

Функциональная часть: офицер должен видеть список обращений, назначенных на него.

Нефункциональная часть по производительности: список назначенных обращений должен открываться быстро, лучше уточнить конкретно, например не дольше 2 секунд при 500 активных обращениях.

Ограничение доступа: офицер не должен видеть обращения других офицеров, если у него нет роли или права на просмотр.

## Задание 5

Функциональные требования:

- руководитель комплаенс должен видеть количество обращений по статусам за выбранный период;
- руководитель должен иметь возможность фильтровать дашборд по подразделению или категории обращения, если это входит в права доступа.

Нефункциональные требования:

- данные дашборда должны обновляться не реже одного раза в 15 минут;
- дашборд должен открываться не дольше 3 секунд при выбранном периоде до 12 месяцев.

Вопрос: какие управленческие решения руководитель хочет принимать по дашборду и какие показатели для этого обязательны?
