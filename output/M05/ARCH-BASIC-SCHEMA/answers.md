| Шаг | Client | Frontend | Backend | Database |

## Задание 2

| Проверка | Где выполнять | Почему |
| --- | --- | --- |
| Описание обязательно | Frontend и backend | Пользователю нужна подсказка, системе нужна гарантия |
| Сотрудник не видит чужие обращения | Backend | Это правило доступа, UI недостаточно |
| Лимит файла | Frontend и backend | Можно предупредить до загрузки, но сервер должен проверить |
| Закрытое обращение нельзя редактировать | Backend | Это правило состояния объекта |
| Корректная дата фильтра | Frontend и backend | UI снижает ошибки, backend защищает запрос |

## Задание 3

Пример:

| Ошибка | Что видит пользователь | Что делает система |
| --- | --- | --- |
| Обращение уже закрыто | "Обращение закрыто, запрос уточнения недоступен" | Не создает уточнение, возвращает конфликт состояния |
| Нет доступа | "Недостаточно прав для действия" | Возвращает отказ доступа и не раскрывает лишние данные |
| Backend недоступен | "Не удалось выполнить действие, попробуйте позже" | Не теряет введенный текст, логирует ошибку |
| Текст пустой | Подсветка поля и текст ошибки | Не отправляет или отклоняет запрос валидацией |

## Задание 4

Базовая схема:

```text
Employee / Officer / Lead browser
  -> Compliance Web Frontend
  -> Compliance Backend API
  -> Compliance Database
```

Внешние компоненты, которые можно добавить позже:

- корпоративный SSO;
- сервис email или уведомлений;
- файловое или объектное хранилище;
- журнал аудита как отдельный компонент;
- BI/отчетная система;
- интеграция с кадровой системой для оргструктуры.
