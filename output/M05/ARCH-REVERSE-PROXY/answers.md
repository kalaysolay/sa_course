# Ответы и ориентиры к практике урока 28

## Задание 1

Reverse proxy нужен как входная точка перед внутренними компонентами Compliance. Пользователь открывает один адрес, а proxy направляет запросы к frontend, backend или reporting. Он может участвовать в HTTPS, ограничениях входящего запроса и маршрутизации.

Важно: reverse proxy не заменяет backend. Он может проверить технические условия входа, но бизнес-правила доступа к обращениям должны оставаться в backend.

## Задание 2

В адресе `compliance.company.local/api/requests` доменом является `compliance.company.local`. Это учебный внутренний адрес системы, который пользователь вводит в браузере. Путь `/api/requests` показывает, к какой части системы относится запрос. Это не папка и не файл, а правило адресации для reverse proxy или backend.

Пример маршрутизации:

| Путь | Куда направить | Зачем |
| --- | --- | --- |
| `/` | Compliance Web Frontend | отдать пользовательский интерфейс |
| `/api/requests` | Requests Backend | операции с обращениями |
| `/api/reports` | Reporting Backend | данные дашбордов |
| `/health` | health endpoint | проверка готовности компонента |

## Задание 3

Балансировщик принимает входящие запросы и распределяет их между доступными экземплярами backend. Если один экземпляр перестал отвечать, балансировщик должен перестать отправлять туда новые запросы и использовать оставшиеся живые экземпляры.

Несколько экземпляров не решают все автоматически, потому что могут остаться общие узкие места: база данных, внешняя интеграция, сессии, блокировки, неверная проверка доступности или ошибки в самой бизнес-логике.

## Задание 4

Примеры требований:

| Идея | Требование |
| --- | --- |
| Единый URL | Пользователи должны открывать Compliance по адресу `compliance.company.local`. |
| HTTPS | Все пользовательские и API-запросы должны передаваться по защищенному соединению. |
| Несколько экземпляров backend | Система должна поддерживать запуск нескольких экземпляров backend для распределения нагрузки. |
| Health check | Инфраструктура должна определять, готов ли backend-экземпляр принимать запросы. |
| Ошибка при недоступности | При временной недоступности сервиса пользователь должен видеть понятное сообщение без потери введенных данных, если это применимо. |
