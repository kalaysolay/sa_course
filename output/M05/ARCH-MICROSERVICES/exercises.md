# Практика к уроку 27

## Задание 1. Найдите возможные границы сервисов

Для Compliance предложите 4-5 возможных сервисов и нарисуйте простую схему их взаимодействия: кто показывает интерфейс пользователю, кто владеет обращениями, кто получает события или данные для отчетности. Для каждого сервиса укажите:

- за какую область он отвечает;
- какими данными владеет;
- с кем взаимодействует;
- почему его можно или нельзя выделять на раннем этапе.

## Задание 2. Разберите событие

Опишите событие `RequestSubmitted` для создания обращения сотрудником.

Нужно указать:

1. Кто публикует событие.
2. Кто может его использовать.
3. Какие поля нужны минимум.
4. Что случится, если один из подписчиков временно недоступен.

## Задание 3. Проверьте обязательность взаимодействий

Для действий ниже решите, что должно быть синхронным, а что может быть асинхронным:

- сохранить новое обращение;
- записать аудит создания;
- отправить уведомление офицерам;
- обновить дашборд руководителя;
- проверить право сотрудника создать обращение.

## Задание 4. Найдите риск преждевременного разделения

Представьте, что команда хочет сразу сделать отдельные сервисы `Requests`, `Gifts`, `Declarations`, `Reporting`, `Notifications`, `Access`.

Опишите 3 риска такого решения для маленькой команды и 3 условия, при которых такое разделение становится более оправданным.
