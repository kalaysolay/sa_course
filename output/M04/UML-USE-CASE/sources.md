## Методические выводы и оговорки

Ассоциации не использовать как дорожку выполнения между овалами. Учебный вопрос «кто участвует и ради какой цели» отделять от «что идёт следующим шагом»; последнюю задачу оставить будущим activity/sequence урокам. «Вход в систему» не добавлять механически в include ко всем целям: уже выполненная аутентификация может быть предусловием конкретного учебного сценария. Include не означает просто «сначала», extend — не любое необязательное поле или любой отказ. Права доступа нельзя выводить только из соединительной линии.

Технические определения давать компактно своими словами. Из спецификаций не переносить их ATM-примеры и большие фрагменты текста. Развёрнутая часть урока — оригинальная пошаговая работа с Compliance, диалог и упражнения с явно заданными допущениями. Совокупный пересказ каждого источника ограничить 200 словами; прямые цитаты не нужны. IBM docs найдены, но открытие вернуло 403, поэтому evidence на них не опирается.
