# AnalystGym — кликабельный макет тренажёра собеседований (SA / BA)

Макет UX будущего SaaS: задачи в стиле LeetCode / Coderun, ревью двумя ИИ-агентами,
диагностика уровня, подборки по доменам, админка справочников.

## Запуск

Вариант 1 — двойной клик:

```
start-mockup.bat        (в корне репозитория)
```

Вариант 2 — вручную:

```
python tasks-mockup/server.py
python tasks-mockup/server.py --port 8080
```

Затем открыть в браузере: **http://127.0.0.1:5180**

> Открывать `practice.html` напрямую из файловой системы тоже можно, но HTTP-сервер
> надёжнее (корректные MIME-типы, будущие fetch-запросы).

Диаграммы Mermaid и PlantUML рендерятся **локально в браузере** — интернет не нужен
(библиотеки лежат в `assets/vendor/`, скопированы из `viewer/public/vendor/`).

Оформление: три темы — тёмная (по умолчанию), серая «IDE» в духе Darcula
и светлая. Выбор — через меню кнопки ◐ в шапке, хранится в `localStorage`
(`sa-trainer:theme`) и применяется до отрисовки страницы, без мигания.

## Структура

```
tasks-mockup/
  index.html            ГЛАВНАЯ analystgym.ru: развилка без шапки/подвала —
                      два полуэкрана (Практика / Курсы) + магнит-диагностика
                      по центру. Диагностика скрыта из навигации всех сайтов:
                      это якорь в контенте, а не пункт меню
  practice.html         лендинг тренажёра (practice-поддомен)
  catalog.html        каталог задач: фильтры, поиск, сортировка (как Coderun)
  collections.html    подборки по доменам
  courses.html        каталог курсов: карточки с лого, ценой, прогрессом
  course.html         страница курса: сайдбар уроков + контент (как viewer)
  task.html           рабочее место: условие слева, вкладки решения справа, ревью снизу
  assessment.html     диагностика уровня (40 вопросов, один на экран)
  results.html        результат диагностики: профиль, план прокачки, разбор ответов
  admin.html          справочники: метки, уровни, подборки, данные макета
  server.py           статический сервер для локального просмотра
  assets/
    styles.css        дизайн-система (графитовый минимализм)
    vendor/           mermaid + plantuml (локальный рендер)
    js/
      data-core.js      уровни, метки, подборки, компетенции, грейды
      data-tasks-1.js   задачи: интеграции + системный дизайн (5)
      data-tasks-2.js   задачи: базы данных + требования (8)
      questions.js      40 вопросов диагностики
      data-courses.js   3 курса: уроки, цены, outcomes
      store.js          состояние в localStorage (решения, ревью, результаты)
      review-engine.js  движок ревью двух агентов (замена на LLM — локальная)
      scoring.js        подсчёт результатов диагностики
      ui.js             шапка/подвал, модалки, тосты, рендер диаграмм
      landing.js / catalog.js / collections.js / task.js /
      assessment.js / results.js / admin.js /
      courses.js / course.js   логика страниц
```

## Домены (как раскладывать по хостингу)

```
analystgym.ru            → index.html (хаб: разводящая на продукты)
practice.analystgym.ru   → practice.html + catalog.html, collections.html,
                           task.html, assessment.html, results.html
course.analystgym.ru     → courses.html + course.html (+ admin.html — внутр.)
```

В макете всё лежит в одной папке, ссылки относительные — при раскладке
по поддоменам достаточно разнести файлы, править ссылки не нужно
(кросс-ссылки между продуктами оставлены относительными осознанно:
в проде это будут абсолютные URL поддоменов).

## Ключевой сценарий для проверки

1. `assessment.html` — пройти диагностику (для скорости есть автопереход по клику).
2. `task.html?id=int-idempotency` — написать пару абзацев решения, добавить диаграмму, нажать «Отправить решение», подтвердить.
3. Дождаться ревью (~7 секунд), страница сама проскроллится к ответу двух агентов.
4. `results.html` — профиль компетенций и план прокачки.
5. `admin.html` — скрыть/добавить метку, проверить, что каталог обновился.

Сброс всех демо-данных: ссылка «Сбросить демо-данные» в подвале.

## Что в макете упрощено (осознанно)

- **Ревью — детерминированный движок** (`review-engine.js`): сверяет текст решения
  с рубрикой задачи, ищет подтверждения, формирует «учтено / не учтено» и вердикт.
  Структура ответа зафиксирована, поэтому замена на LLM-агентов не меняет интерфейс.
- **Данные — в браузере** (`localStorage`): решения, попытки, результаты диагностики,
  правки справочников. Бэкенда нет.
- **Оплата** — заглушка-модалка на лендинге.

## Навигация и мелочи (зафиксировано)

- Логотип везде ведёт на хаб (`index.html`); из футеров — ссылка «AnalystGym — платформа».
- Мобильное меню: бургер на ≤860px (шапка `ui.js`, стили `.main-nav.open`).
- Кнопка результатов ведёт в каталог с метками пробелов (`levelCatalogUrl`).
- Favicon (`assets/logo.png`) на всех страницах. Полная спека: `docs/product-spec.md`.

## Контент курса: вшит сборкой (работает и как файл, и на хостинге)

Уроки курса «Системный аналитик до мидла» повторяют реальную структуру
программы (модули M01–M11 из `course/curriculum.yaml`). Тексты первых уроков
модулей подтягиваются из `output/` репозитория курса:
`lecture.md` → раздел «Лекция», `exercises.md` → «Упражнения»,
`answers.md` → под катом внутри упражнений, `project/task.md` → «Артефакты».
Рендер Markdown — `assets/js/md.js` (диаграммы mermaid/plantuml рисуются
локально, как в задачах).

Как это работает технически: `scripts/build-content.ps1` упаковывает
`output/*/*/lecture.md` (+exercises, answers, project/task.md) в JS-модули
`assets/content/<TOPIC>.js`. `<script src>` работает и на file://, и на http —
в отличие от fetch, поэтому страницу курса можно просто открыть двойным кликом.
`course.js` сначала смотрит встроенный кэш, потом догружает модуль, и только
потом пробует fetch из `../output/` (для свежих уроков без пересборки).

Пересобирать после каждой регенерации `output/` издателем:
`powershell -ExecutionPolicy Bypass -File tasks-mockup/scripts/build-content.ps1`
(флаг — только на один запуск, системную политику не меняет). Сборка также
упаковывает `project/compliance/business-analysis/*.md` в
`assets/content/__artifacts.js` — витрину артефактов сквозного проекта.

Диплинки на виды урока: `course.html?id=sa-middle&lesson=REQ-FNFR&view=artifacts`
(`view=lecture|exercises|artifacts`) — можно делиться ссылкой на раздел.

- Задач: 16 (лёгких 3, средних 8, сложных 5).
- Вопросов диагностики: 40+, 7 компетенций.
- Меток: ~60 в 11 категориях. Подборок: 6.
- У каждой задачи: условие, рубрика для ревью, стартовые вкладки, подсказки,
  вопросы интервьюера, эталонное решение автора.
